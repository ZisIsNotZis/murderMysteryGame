## 为什么做这个本

《寿宴》是一份已经写完、可以直接实体开桌的民国宅门剧本杀：6 本角色本、1 本主持人手册、32 张线索卡，以及背后的诡计规格书和验证记录。

它同时想回答一个更难的问题：

> 一个推理故事，能不能**不靠说谎**完成误导？

多数公平推理会藏信息、让叙述者不可靠，或者把关键事实留到最后一刻。这个本反过来：该给的事实都摆在桌上，文本从不撒谎。误导来自玩家自己带进桌的默认假设——所有信息都看得见，但看见不等于读懂。

揭示之后，前文每一句仍然字面为真；只是你会发现自己一直读的是另一层。

## 快速开始

不用安装、不用联网、不用 APP。打印，入座。

1. **主持人预习**：先读 [`script/host-manual.md`](script/host-manual.md) 的开场契约与七阶段跑表。
2. **打印一套材料**：[`script/`](script/) 里的 6 本角色本、主持人手册、32 张线索卡。
3. **按手册开桌**：开场 → 自我介绍 → 两轮搜证 → 指认 → 复盘。NPC 问答、卡池发放、提前翻面分支都写在手册里。

| 你需要 | 说明 |
|---|---|
| 玩家 | 6 人；建议至少 2 人玩过 1–2 次剧本杀 |
| 主持人 | 1 人；需提前通读手册 |
| 打印材料 | 6 本角色本 + 主持人手册 + 32 张线索卡 |
| 其他 | 纸笔、计时器；可选信封或卡套 |

主持人只答事实，不替玩家推理，也不临时改设定。玩家如果提前接近真相，手册里有压缩分支，不需要救场式否定。

## 现在能做什么

- **一套完整的开桌材料**——6 本角色本、1 本主持人手册、32 张线索卡、7 个计时阶段、NPC 问答卡和分支复盘。
- **公平的误导**——不藏线索、不截半句、不让叙述者撒谎；凶手的不在场证明全部由公开真话构成。
- **两次独立翻面**——双层诡计各翻一次面，互相正交，各自都有前置伏笔。
- **22 条承重句**——在表层读法与真相读法下都字面为真，完整映射见 [`spec.md`](spec.md)。
- **主持人友好**——固定开场契约、线索池预算、NPC 问答、150 分钟跑表（可延至 180）和复盘脚本。
- **过程可审计**——设计宪法、规格书、线索台账、红队审查、一致性审计和两场盲测实录都在仓库里。

本作正文为中文。英文 README 负责让非中文读者理解设计方法与项目状态，它不是一份可开桌的英文译本。

## 怎么开发

这个本有几条硬约束。改任何一句之前，先读：

1. [`spec.md`](spec.md) §7「写作规范锁」——唯一指称、禁止句、线索噪音化写法；
2. [`spec.md`](spec.md) §1.2「逐时客观事实表」——角色口中的行为必须能在表中找到；
3. [`spec.md`](spec.md) §九「修订记录」——已有修订的原因与联动改动。

改完后至少重跑：

- 违禁词与指称检查（管家／园丁、死亡时刻声明、人数断言）；
- 22 条双读映射的真值抽验；
- M/S/K 线索台账落位检查；
- 一场盲测，观察是否出现提前翻面、无法收束的 K 线或主持人临时补设定。

`.scratch/` 里的 stage 脚本是当时 agent 工作流的历史存档，记录的是流程，不是一键测试，不保证今天能直接复跑。

## 怎么参与

欢迎 issue 和 pull request，尤其是真人试玩报告、公平性批评、错字与一致性问题。

- **不要在 issue 标题或玩家可见的公开讨论里直接写真相。** 剧透写法见 [`CONTRIBUTING.md`](CONTRIBUTING.md)。
- **守住不变量。** 任何增加谎话、藏线索或改动事实的修订，必须同时更新 `spec.md` 与相关台账。
- **说清你测了什么。** 报告里带上阶段、桌面构成，以及出问题的那句原文，会比「感觉不对」有用得多。

完整检查清单见 [`CONTRIBUTING.md`](CONTRIBUTING.md)。

## 设计（剧透，点击展开）

<details>
<summary><strong>展开查看双层诡计与设计原则</strong></summary>

- **主诡计《死亡在下午》**：全篇不声明死亡时刻。玩家默认「发现时刻（20:30）≈ 死亡时刻」，于是把所有行踪和不在场证明都锚在晚间。真相是死者死于当天下午未申之交（约 15:00），晚宴全程人已经死了，晚间每一场「冲突」都是死讯之后的余波。凶手的诡计全部由公开真话构成：他精心做的晚间不在场证明，恰恰反证了「全桌都没看见下午」。
- **副诡计《一人双职》**：仆役老陈同时担任管家与园丁。全篇从不断言这是两个人，玩家按「职务数 = 人数」的人事图式自己多算出一个「园丁」。
- **双读皆真**：22 条承重句在表层读法与真相读法下都字面为真。全篇角色零谎话，死者零「死亡时刻」声明。
- **公平性**：主诡计的物证线、人证线、纸面加固线多路可达；线索卡是「背景噪音」而不是聚光灯；主持人不捂嘴、不临时补设定。
- **结构**：两诡计正交（时间账 × 人数账），复杂度收敛；复盘固定先时间线、后人数账。

完整设计见 [`spec.md`](spec.md)，逐句导读见 [`ying-yan.md`](ying-yan.md)。

</details>

## 路线图

### 已实现

- **v1.0 完整套件**——6 本角色本、主持人手册、32 张线索卡、七阶段流程、两次翻面。
- **规格红队**——公平性、结构、表层三路独立审查；修复 1 个 P0（凶手一句双假话，击穿「零谎话」最高硬约束）。
- **成稿一致性审计**——指称、违禁句、22 条双读真值全部检查；M/S/K 台账全部落位。
- **两场盲测**——普通桌与老手桌各一场，由 LLM 扮演玩家和主持人完成；实录见 [`playthrough.md`](playthrough.md)。
- **作者试玩**——作者实际体验后接受本作作为 AI 写剧本杀的 POC，目标达成。

### 计划中

- [ ] 真人整桌 1–2 场，按 [`.scratch/blindtest-1.md`](.scratch/blindtest-1.md) 的观察维度记录。
- [ ] 卡面实体化：补美术、排版与材质，但不得增删或改动任何事实句。
- [ ] 依据真人试玩证据修订，并把每次改动记入 `spec.md` §九。

### 未来愿景

长期目标是一套可重复的「AI 辅助公平推理」写作方法：先写真相，再让每一句都经得起两种读法，最后让桌面自己发现它带进来的认知框架。这个本是概念验证；下一步不是加功能，而是拿到真人桌面的证据，并留下能看懂的修订轨迹。

## 已知边界

- **尚未做真人整桌实测。** 两场盲测由 LLM 扮演玩家和主持人，能验证文本自洽、信息可达与流程分支，但不能替代真人的阅读节奏、社交动态和主持人临场压力。
- **卡面为精简文字版。** 目前面向打印，不是最终美术。实体化可以加排版与质感，但不得增删事实句。
- **时长偏紧。** 150 分钟是下限；6 人双诡计建议预留 180 分钟。
- **不是软件产品。** 没有 Web／APP、语音或自动计分。
- **流水线脚本是历史存档。** 它们记录流程，不是受支持的构建。
